# Roadmap and acceptance

| Phase | Dependency | Acceptance evidence |
|---|---|---|
| 1 · Initialization | Existing main branch, Python and Node | Versioned roadmap, environment example, tracked milestones |
| 2 · Design system | Approved identity | Palette, self-hosted typography, custom SVG brand, visitor-local themes |
| 3 · Homepage | Design system | Accessible navigation, entrance, cursor, editorial hero and footer |
| 4 · Environments | Public shell | Floating islands, architecture layers, dual-mode workspace, booth and optional orbital viewer |
| 5 · Content | Reviewed project facts | Four case studies, learning, certificates, Markdown publishing and résumé integration |
| 6 · Services | Database schema | GitHub APIs, SMTP, health, event collection, secure sessions and migrations |
| 7 · Administration | Owner account | Protected date-filtered charts, receipts, metrics and logout |
| 8 · Verification | Public and private flows | Unit, contract, browser, local SMTP, responsive layout and Lighthouse evidence |
| 9 · Infrastructure | Container-capable environment | Docker build, Nginx, PostgreSQL, Compose readiness, CI and deployment instructions |
| 10 · Audit | Hosted checks | Requirement matrix, reviewed screenshots, verified main and documented external inputs |

The design and feature acceptance matrix is in DELIVERY.md. TEST_REPORT.md records measured outcomes. ASSET_REQUIREMENTS.md identifies owner-controlled content. DEPLOYMENT.md covers environment configuration and deployment to an existing host.
